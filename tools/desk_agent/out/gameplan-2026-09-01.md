**Wall 3 — the agent's `python` is not the repo `.venv`, so chart images fail.**

```
pytest tests/test_desk_levels.py -q  ->  25 passed, 1 failed
  test_the_chart_renders_headless_to_a_file
  ModuleNotFoundError: No module named 'matplotlib'   (desk_levels.py:521)
```

`matplotlib` is declared in `requirements.txt` line 10 and is present in
`.venv/Lib/site-packages/`. It is absent from the interpreter this job actually
runs on: `where.exe python` resolves to the system Python 3.12 install first,
and the import genuinely failed inside the running process, so this is observed
rather than inferred from a path.

The cause is in the launcher. `run_job.ps1` lines 93–94 resolve
`$RepoRoot\.venv\Scripts\python.exe` — but only to write the *fallback failure
record* at line 119. Nothing puts that venv ahead of the child process's `PATH`,
so every `python` the agent itself runs is the system one.

Scope, stated precisely so this is not read as worse than it is: the
`matplotlib` import at `desk_levels.py:521` is **inside** the render function,
so this breaks chart images only. Levels, `--markdown` and `--json` need
`pandas`/`yfinance`, which the system interpreter does have — 25 of 26 tests
passed on it. So Wall 3 costs the pictures, not the numbers.

Item 1 alone restores the gameplan tomorrow. Item 2 is what stops the chart step
failing on the day someone first asks for an image.
