## Correction: the permission line alone is NOT proven to fix tomorrow

Yesterday's report closed with *"Item 1 alone restores the gameplan tomorrow."*
That claim was over-stated, and if it is acted on alone there is a real chance
tomorrow fails again on a different error.

The evidence yesterday used was `pytest tests/test_desk_levels.py` giving 25
passed, 1 failed on the agent's interpreter — read as proof that everything
except the chart works there. Re-run today, identical result:

```
pytest tests/test_desk_levels.py -q  ->  25 passed, 1 failed
  test_the_chart_renders_headless_to_a_file
  ModuleNotFoundError: No module named 'matplotlib'   (desk_levels.py:521)
```

But those 25 passes prove **`pandas` only**. `pandas` is imported at module
scope (`desk_levels.py:60`), so any passing test proves it present. `yfinance`
is not: it is imported lazily inside `fetch_bars`, and the function's own
docstring at `desk_levels.py:169-170` says so in as many words —

> `"""The one network call in this file. No test reaches it."""`

So the suite cannot and does not exercise the only code path that actually
fetches bars. Whether `yfinance` imports on the interpreter this job runs on is
**unproven**, and I could not settle it from here: `python -c` is denied, and
reading the system interpreter's `site-packages` directly returns *"File is in a
directory that is denied by your permission settings"* — there is an explicit
deny on `AppData`. That is a hard stop, not a thing I declined to try.

**Consequence for the fix:** the four permission lines make the command *run*.
Putting the repo `.venv` on the agent's `PATH` is what makes it *work*, because
the venv has `pandas`, `numpy`, `matplotlib` and `yfinance` all four. Do both in
one pass, or budget for the possibility of a fourth blocked morning.

## The fix, as one paste

Three reports have now described this fix in prose and none of it has landed.
Prose is not a repair, so here it is as something runnable. This edits
`.claude/settings.json` — inserting four grants after the `runlog` line — and
then answers the open `yfinance` question in the same breath.

```powershell
cd C:\Users\Gexio\OneDrive\pwb-toolbox; $f = '.claude\settings.json'; $t = [IO.File]::ReadAllText($f); if ($t.Contains('desk_levels.py')) { 'ALREADY THERE - nothing changed' } else { $a = '      "Bash(python3 -m tools.desk_agent.runlog:*)",'; $n = $a + "`r`n" + '      "Bash(python tools/desk_levels.py:*)",' + "`r`n" + '      "Bash(python3 tools/desk_levels.py:*)",' + "`r`n" + '      "Bash(python tools/backtest_lab.py:*)",' + "`r`n" + '      "Bash(python3 tools/backtest_lab.py:*)",'; $t2 = $t.Replace($a, $n); if ($t2 -eq $t) { 'FAILED - anchor line not found, nothing written' } else { [IO.File]::WriteAllText($f, $t2, (New-Object Text.UTF8Encoding $false)); 'ADDED - now ' + (Select-String -Path $f -Pattern 'desk_levels|backtest_lab').Count + ' matching lines' } }; python -c "import yfinance; print('yfinance OK', yfinance.__version__)"
```

Success looks like two lines: `ADDED - now 4 matching lines`, then
`yfinance OK <version>`.

- If the second line is a `ModuleNotFoundError` instead, that is the unproven
  case landing on the bad side, and the launcher fix below is **required**, not
  optional.
- `ALREADY THERE` means someone already added it and only the second line
  matters.
- `FAILED - anchor line not found` means the file moved on since this run read
  it; nothing was written, and it needs a session to do it by hand.

## The launcher fix — flagged, deliberately not made

`run_job.ps1` line 98-99 resolves `$RepoRoot\.venv\Scripts\python.exe`, then
uses it **only** to write the fallback failure record. The agent itself is
launched further down with no venv on `PATH`, so every `python` this job runs is
the system one. Prepending `$RepoRoot\.venv\Scripts` to `PATH` for that
invocation is the whole change.

I did not make it. It changes which interpreter the agent runs, which is a
widening of my own capability by any honest reading of the guardrail; it cannot
be tested from inside the run it would affect; and getting it wrong breaks every
future scheduled run rather than one. That is a human's call, and it is one line.
